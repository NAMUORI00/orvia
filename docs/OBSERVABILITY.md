# Infrastructure observability

Orvia collects only registered container metadata. The broker samples at roughly 60-second intervals: runtime status, CPU, memory, block I/O, interface byte/packet/error/drop counters, GPU utilization/VRAM/temperature/power, system memory/load and laboratory storage usage. A sample failure does not interrupt research. UI requests read cached samples and never execute workload probes.

Process names (not arguments, environment, command history or file contents) are refreshed every five minutes. These names do not identify research intent, prove a job is training, or verify an SSH connection. Container running status is distinct from externally reachable service health. Shared container networking would require separate accounting; normal Orvia accounts use individual bridges.

SQLite records under `/var/lib/h200-console/telemetry.sqlite3` are root-readable with seven-day retention. The UI charts up to about 120 interval-end samples over 2 hours, 24 hours or 7 days, marks delayed data and leaves rates N/A until two compatible samples exist. Byte and packet deltas reset across container replacement/restart. State-change records include stop/start/restart, missing storage mounts and crossing 90% storage usage. No packet payload, destination, full command, password or user file content is collected. Collection starts at installation; historical records are not fabricated.

Storage analysis runs on demand in one low-priority worker at a time (`nice 19`, idle I/O priority). Results are cached for 15 minutes. Scans read filesystem metadata only, include hidden caches, skip symbolic links, other filesystems and administration directories, and count hard links once. Each scan is bounded to 45 seconds / ten million entries / 512 MiB address space, with partial results explicitly labelled. Directory detail is retained to four levels; only the largest 30 entries at each selected path are returned. Account attribution follows each home workspace, not POSIX file ownership. Filesystem overhead and unscanned areas remain in the other/system segment. A scan is not an atomic snapshot while research files change.

Product branding is Orvia. Existing service names, Unix sockets, storage paths, labels and configuration filenames remain compatible during upgrades; the rename does not migrate or recreate researcher containers.
